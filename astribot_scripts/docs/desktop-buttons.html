Usual order
Power On & Home Robot (when needed) → Start Astribot → Record RGB-D MCAP

What each button does

Desktop buttonAction and what to expect
Power On & Home Robot Powers on the robot, confirms power, activates the drives, and confirms activation. It then waits five extra healthy seconds, requests the vendor WEB → PC control handoff, confirms release, and runs the SDK home routine. The terminal reports success only after home is verified. It stays open afterward; press Enter to close it.
This performs physical motion and opens the grippers. It does not start the observation stack. Reusing the button on an already active robot still requests homing.
Start Astribot Starts the sensor publishers, rear-lidar FAST-LIO, robot visualization, and one RViz window on this remote PC. RViz uses map as its fixed world frame and shows the robot, map, odometry history, camera images, and configured frame axes. Wait for startup success and check that the camera images update.
If the observation session is already running, this button restarts it and begins a fresh map and trajectory. It does not power on, activate, or home the robot.
Record RGB-D MCAP Opens a terminal and records RGB and depth from the four cameras listed below. A new timestamped recording folder is created automatically. Leave the terminal open while recording. Press Ctrl+C in that terminal to stop and finalize the files. Repeat clicks cannot create a duplicate recorder. If publishers are absent, it waits for their topics.
Stop Astribot Stops this observation session, including its sensor publisher, FAST-LIO, robot visualization, and RViz. It leaves the robot controller and camera/lidar drivers active. It does not stop the separate recorder, deactivate the robot, or power it off. Stop recording with Ctrl+C first. This button also succeeds when the observation session is already stopped.

Start a recording

  1. If the robot is off or inactive, use Power On & Home Robot and wait for “Startup complete.” If it is already active and positioned for work, skip this button to avoid another home motion.
  2. Click Start Astribot. Wait for startup success and confirm that the four camera views are updating in RViz.
  3. Click Record RGB-D MCAP. The terminal prints the recording folder and topic names. The terminal shows how many RGB and depth frames each camera has saved.

Before homing: keep the robot’s motion area clear and make sure the grippers are not holding an object. Startup refuses other SDK controllers and VR/joystick/drag modes. It stops on a failed transition; it does not blindly retry or force power off.

Images and recording files

The recorder samples each of the eight topics at 3 Hz. RGB images use rgb8 at 640 × 480. Depth images use 16UC1 at each camera’s native depth resolution. All eight use sensor_msgs/msg/Image and retain their camera timestamps.

Each click uses a new folder:

/home/fourier/astribot_sdk_ros2/recordings/raw_rgbd_YYYYMMDD_HHMMSS/

The folder contains numbered .mcap files and metadata.yaml. Files roll over at 3,990,000,000 bytes (3.99 GB), leaving room for final messages and indexes below the requested decimal 4 GB limit for these configured image sizes. Keep the entire folder together when copying a recording.

This button records camera messages only. Use OBS separately for a screen video of RViz or the desktop. The recorder saves received frames; network losses or camera startup delays can create gaps.

Finish the session

  1. Focus the recording terminal and press Ctrl+C. Wait for recording to finish and the terminal to exit. This lets rosbag2 finalize the MCAP files and metadata.
  2. Click Stop Astribot to stop the observation stack.
  3. When finished with the robot, run the separate shutdown command below on the remote PC. It deactivates the drives, waits for confirmation, then powers off and confirms completion.
/home/fourier/astribot_sdk_ros2/astribot_scripts/robot_power.sh stop --execute

Robot shutdown is a separate terminal command; the red Stop Astribot button controls the observation stack only.

If something does not start

What you seeWhat to check
Recorder is waiting for topicsStart Astribot and check that camera images are arriving. The recorder needs the camera drivers to be streaming.
“Recording already running”Use the existing recording terminal. Stop it with Ctrl+C before starting a new recording.
RViz opens but data is missingCheck the Start log for the missing stream or transform. Confirm the robot network is connected and the robot is active for joint feedback.
Robot startup failsRead the terminal and its saved log. If another SDK controller or teleoperation mode owns control, end that session before retrying. A delay cannot resolve a persistent ownership conflict.
